# AQG 夜跑（aqg-nightshift）

一句话：**能自动做的做完并留证据，需要人拍板的停下写进「待拍板」，绝不顺手替用户决定。**

进度唯一来源：`docs/priority-2026q4/06-统一待做与排期-2619.md`（下称 06）。今晚执行日志：`docs/priority-2026q4/08-夜跑执行日志-<mmdd>.md`（下称 08，没有就按 §5 模板新建）。

## 1. 开工前（顺序不可换，不可跳过）

1. 读 06 §四 各窗口表，取未打 ✅ 的 T 项；与 [QUEUE.md](QUEUE.md) 的准入判据求交，得到今晚队列。
2. 打零污染基线：`bash .qoder/skills/aqg-nightshift/scripts/baseline.sh snap`
3. 记录回归起点：`.venv/bin/python -m pytest -q`（条数只读不改）与 `.venv/bin/python scripts/verify.py`（默认仅离线；**注意它会跑两遍 `build_suite` 从而改动 `cases/` 的 mtime，内容不变——所以基线一律用内容指纹，不用 mtime**）。
4. 把队列、起始条数、HEAD 写进 08 的「开工快照」。

## 2. 红线（任一命中即停该项，不许"就这一次"）

| 禁止 | 原因 |
|---|---|
| `git push` / `commit` / `add` / `reset` / `rebase` / 切分支 | push 与提交粒度逐次经用户同意；改动一律留在工作区 |
| 删除或移动任何文件（含死产物、备份集） | 删除类动作须另行确认 |
| 写 `reports/**`、`cases/**`、`models*.json`、`workspace/**` | 评测事实与配置只读；重放旧 `report.md` = 篡改历史 |
| 调用任何模型（跑批、`rejudge`、`probe`、`verify --live`） | 耗 token 且改变产物 |
| 为让回归变绿而放宽断言／调低阈值／扩大豁免／改判据 | 判据不得由被它评价的循环修改（见 `docs/quality/01` §五） |
| 改 `dataset_epoch`、动题面、切代 | 切代只在 W5b 窗口打包做 |
| 在 README「测试与 CI」之外新增任何单测条数声明 | 条数单点声明（T11）。反向义务：用例数变了必须同步中英两处声明（见 §4.3） |

**唯一允许的 git 写操作**：`git restore -- <自己刚改坏的单个文件>`，用于把该项回退到取证前状态。

## 3. 准入判据（三条全满足才能自动做）

1. 零 token、纯本地；
2. 改动可按单文件回退，且不触碰 §2 的只读路径；
3. 不产生对外口径变化（不改已入库的对外产物、不新增对外承诺）。

代码改动必须**同批**配单测（项目纪律：含业务逻辑的代码必须有单测，否则不许入库）。

今晚排定的队列与逐项验收见 [QUEUE.md](QUEUE.md)；其中标注 🔒 的是「必须停下来等用户」的项，只登记不执行。

## 4. 单项执行循环（每项跑满 6 步，禁止合并或跳步）

1. **取证**：用 `grep`／读文件实测当前状态与真实行号——不引用记忆、摘要或上一轮的行号。
2. **实施**：按验收目标做最小改动，风格与周边代码一致。
3. **补测**：新增或修改单测覆盖本次行为与边界。**用例数一旦变化，同一批把 `README.md` 与 `README.en.md`「测试与 CI」两处声明改成新的 collect 数**（`.venv/bin/python -m pytest -q --collect-only` 取）——T15 起 `verify` 的「声明条数自检」会比对它，忘改或只改一份都直接判红，不是可选项。
4. **回归**：`.venv/bin/python -m pytest -q` 必须 **0 失败**且条数 ≥ 起始条数；再跑 `.venv/bin/python scripts/verify.py`，离线项必须全 OK。**变红不许靠改断言抹平**——回退该项并在 08 标 ⛔ 与原因。
5. **零污染复验**：`bash .qoder/skills/aqg-nightshift/scripts/baseline.sh check`。报 🛑 时**立刻全停**（见 §6）。
6. **写日志**：在 08 对应小节填实况（改了什么、验收命令与其**实际输出**、遗留、下一步建议），并在 06 对应行更新状态。

**06 的写法纪律**：历史条目与已归档原文不重写；完成项在验收列写「✅ <日期> 完成（实况）」；若原验收口径不可执行或与事实冲突，写「验收口径改判」并给理由，不要偷偷降低标准。

## 6. 停机与收尾

- **全停条件**：`baseline.sh check` 报 `reports/`、`cases/`、`models*.json` 内容变化，或 HEAD 移动、或出现暂存内容 → 停止一切写入，在 08 顶部标 `🛑 已全停` ＋ 差异原文，等用户处理。
- 单个队列项连续两次回归失败：标 ⛔ 回退，继续下一项，不熬夜死磕。
- 队列跑完或时间到：**只做写日志与登记待拍板**，不额外扩张范围；收尾必须在 08 留下「汇总 + 待拍板 + 建议提交切分」三段。

## 7. 次日汇报（用户说"看进度／昨晚跑了什么"时）

先读 08，再按 **状态 → 实测证据 → 待拍板** 三段汇报；引用的数字必须当场重跑命令得到，不得复用日志里未复核的数字。
