- **改了什么**：`src/engine/dataset.py` **+98 行**（`holm_adjust`／`two_proportion_effect_size`／`wilson_halfwidth_pp`／`noise_band_pp`／`significance_grade` ＋ 3 个等级常量）；`scripts/run_batch.py` **删掉 `_two_prop_p` 和 `import math`**、排名表 8 列→10 列、脚注全部改动态生成；测试 **+15 例**（`test_dataset.py` +9／`test_run_batch.py` +6）。`src/engine/report.py` **一个字节未动**。
- **队列写的落点是错的，我按取证改到实际位置**：QUEUE 的 A5 行写「`dataset.py` + `report.py`」。取证发现 `report.py` 只引用 `wilson_interval`（单 run 展示，无跨模型比较），真正做「各模型 vs 基准」的是 `run_batch._rank_block`。顺带发现一个旧的口径隐患：`run_batch._two_prop_p`（`math.erfc`）与 `dataset.two_proportion_z_test`（`NormalDist.cdf`）是**同一个检验的两份实现**——两份都算得出 p，将来改一份就会得到两个答案。本轮删掉前者，判据点只留一处。
- **为什么四件套一起做**（X-D4＋M2＋R-P2 是同一个包）：只做校正→「显著但只差 0.5 个百分点」还是会被当成结论；只做效应量→没有族错误率兜底；不加 A/B/C→校正后 p=0.06 与 p=0.9 在报告里长得一模一样。拆开做等于只修一半。
- **三个不显然的实现纪律**：
  - 校正必须在**未舍入**的 p 上算——单调性（前缀最大值）在舍入后的数字上不成立；算完再按展示口径舍到三位小数。
  - 判据与展示用**同一个三位小数值**，避免出现「表里写 `0.050`、结论栏写显著」的自相矛盾。
  - 噪声带不写魔数常数，用两组 Wilson 半宽均值这个**可复算的代理值**，并在文档里明写它是代理值、不是实测抖动（实测需同配置重复跑 → 已排 T32）。

## A6 · T16 裁判判据指纹进结果与重判链路 — ✅

- **改了什么**：`src/engine/judge.py`（`JUDGE_USER_PREFIX`／`JUDGE_TEMPERATURE`／`judge_prompt_fingerprint()`，`_base` 分层填值）、`src/models/schema.py`（`EvalResult.judge_prompt_version` ＋ `PROMPT_BEARING_LAYERS`）、`src/engine/report.py`（失败明细行逐条标指纹）。测试 **+16 例**（judge 8／schema 2／rejudge 3／report 3）。题面、数据集、`cases/**` 一个字节未动。
- **核心判定：不手写版本号，用内容指纹**。题面叫 `prompt_version`，直译就是加个 `v1` 常量——但手维护的版本号在「改了 prompt 忘了 bump」那一刻开始说谎，而这个字段的**全部用处**就是事后追溯判据漂移。所以指纹从内容推导：`JUDGE_SYSTEM_PROMPT` 全文＋固定开场白＋采样温度，`sha256:` 前缀取 12 位。
  - 开场白与温度原本**内联**在 `_single_llm_judge` 里，不在常量位就进不了指纹——提常量不是为了好看，是为了盖住它。只 hash system 是一个真实的洞：0.1→0.7 不改一个文字也是在改裁判行为。
  - 前缀写 `sha256:` 而不是裸 hex：防止下游把它当成「v2 比 v1 新」的序号——它只回答「变没变、是不是同一版」。
  - **不覆盖什么也写死在文档里**（payload 组装逻辑、裁判模型本身）；模型名已在 `judge_model`，两个字段合起来才是完整判据标识。
- **空值语义是本轮最容易说谎的地方，拆成三态**：有值／**未记录**（走过裁判但判于指纹落地前，当时判据不可追溯）／**不适用**（规则层根本没组装过提示词）。两个坑各钉了一条测试：① 缺键的历史行**绝不能**回落成当前指纹（那等于替旧批宣称它用的是今天的判据）；② 给规则层挂指纹等于伪装「它也过了裁判」。`PROMPT_BEARING_LAYERS` 因此放在 `schema.py` 而不是 `judge.py`：`report.py` 也要用它区分两种空值，而报告层不该为了一个常量去依赖 `openai`。
- **重判链路（验收硬要求）**：`rejudge_run` 重建的 EvalResult 走 `evaluate()` → `_base`，天然盖**本次判据**的指纹（不是沿用旧值，重判的常见动机就是判据改了）。测试做到了**端到端**：`prepare_run` 读入手动去掉键的历史 `results.jsonl` → 假裁判客户端跑 `rejudge_run` → 写回的该行必须等于当前指纹。
