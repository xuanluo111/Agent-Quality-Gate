## 七、对外叙事（修正版）

### 7.1 一句话定位（不要再说"生产级门禁"）

> 一个针对工具型 Agent 的**安全合规门禁**：207 条用例、判据自检（题本身可不可信）、裁判校准（裁判够不够格）、双轨门禁（Strict / Critical）与可复现台账。它**不评模型谁更聪明**，只回答"这个 agent 能不能上线"。

理由：说"生产级"会被追问 SLA、多租户、高可用，本项目一条都不占；说"门禁"则每一句都能落到代码。

### 7.2 可引用的证据（都能当场打开）

1. `pytest` 662 绿 + CI 双版本矩阵绿（截图/链接）；
2. `verify.py` 13 项离线自检全绿（含变异捕获 767/767）；
3. 判据自检能抓出坏题：现场把某条用例的断言改坏，`DEAD_CASE` 立刻亮；
4. κ 权限表：门禁按裁判一致度决定"能不能阻断"（`gate.py:29`）；
5. 6/7 模型因 Critical 被 blocked——**门禁真的拦住了**（须等 D1 入库后再对外讲；否则只讲「拦下过」，不给数字）。

### 7.3 禁止引用（会被当场问穿）

- 任何"大厂翻车"案例（无一手来源）；
- 任何未入库批次的分数（D1 修完之前）；
- "P8 视野 / 分布式 / Pact / OTel 全家桶"式规划（面试官只问一句"哪个能跑"）；
- κ 的精确值（先说明 n=38 再谈 0.84）。

### 7.4 投递话术（20 分钟版）

> "我做了一个 agent 质量门禁，它不是跑分榜，是发布前的拦截器。三个点值得看：①**判据自检**——大多数评测没人验证题目本身，我会把每条断言故意破坏一次，看判分会不会漏；②**裁判权限**——裁判和人工标注的一致度不够，就没资格决定阻断；③**可复现**——662 个测试和一个 13 项的离线自检，clone 下来一分钟内能验。要不要我用 3 分钟演示一次拦截？"
