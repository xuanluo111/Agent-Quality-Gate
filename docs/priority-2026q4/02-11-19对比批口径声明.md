# 11/19 对比基线批 · 口径声明

> **用途**：本批是 AQG 第一个**可对外引用**的对比基线。凡引用本批数字的场合（报告、图表、对外材料），必须同时给出 §二 的全部复现锚点与 §三／§四 的限制；**§二 缺任何一行，该数字视为不可引用**。
> **状态**：11-14 成稿（`cca9da3` 上实测）→ 11-18 冻结 → 11-19 跑批后按实跑回填 §二／§六／§八。

## 一、本批是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 7 个模型 × `core_suite` **207 条全量** × `repeat=2` 的**同代**横评 | **不是排行榜**：不出总排名，只出分项与适用条件（M2 报告改版的口径前身） |
| 判据侧已有机器背书：C01 自检 `dead=0/leaky=0`、C02 κ=0.8412 三档权限、C04 可判率 205/207、K13 豁免 9 条、C14′ fixture 预检全通过 | **不是模型能力上限**：受 harness 预算约束（`max_tokens=4096`／`token_budget=24000`／`max_rounds=4`／`case_time_budget=480s`），预算收紧会把"没答完"记成不合规 |
| 同代内可复现：数据集代际、抽样、种子、判据资产全部落盘 | **不是跨代可比**：与 `f6871e25`、`db2add`、`2fd4a5646accb8d7` 等前代**分数不可相减**，只能比"哪些用例失败"这一集合层面的迁移 |

参评模型（`models.json` 的 `name`，共 7 个）：`tokendance-spark-x2.5-4b`／`diandian-dots3-note-pre`／`zhipu-glm-4.5-flash`／`tokendance-mimo-v2.6-flash`／`tokendance-spark-x2.5-1.7b`／`tokendance-step-3.5-flash`／`tokendance-ling-3.1-flash`。同一 `base_url` 下的多个模型**不是**同一个系统，引用时不得合并。

## 二、复现锚点（引用时必须给全）

| 项 | 本批取值 | 从哪读 |
|---|---|---|
| 数据集代际 `dataset_epoch` | `deff7501007cff61` | `reports/risk_ledger.json` |
| 题库 | `cases/core_suite.jsonl`，207 条 | `cases/suite_manifest.json` 的 core sha |
| 采样 | **全量**：`sampling.method == "full"` 且 `population == sample == 207` | 每个 run 的 `summary.json.sampling` |
| 抽样种子 | `seed=42`；`repeat` 第 k 次尝试 = `(42 + k×7919) mod (2³¹−1)`，k=0 保持 42 | `summary.json.seed` ＋ `runner.attempt_seed`（`runner.py:228`） |
| 重复次数 | `repeat=2`、`require_stable=true` → 结论以 **pass^2** 为准 | `summary.json.repeat` |
| 模型版本 | 以 `run_meta.model_version` 为准，**不从 `base_url` 推断** | 每个 run 的 `run_meta.json` |
| 门禁阈值 | `jcv_threshold=0.6`（`judge.py:1453`）／`min_valid_rate=90`（`gate.py:172`）／`breaker_threshold=5`（`run_eval.py:100`） | `src/config.py:83/87/105` |
| 提交号 | 跑批时 `git rev-parse HEAD` | 写进批报首页 |

**分母口径的硬约束**：`limit` 必须为 `0`（或 ≥ 207）。**当前 `models.json` 每个模型写的是 `limit: 150`**，直接跑会静默降成"150 条分层抽样"——`sampling.method` 变成 `stratified_category_severity`、`sample=150`。此时本批**不是全量批**，通过率不得与 207 全量批相减，§二 第一行须改写为 150 并在标题注明"抽样批"。

## 三、与 `20261106-night` 的三处不可比（声明里必须原文出现）

| 维度 | `20261106-night` | 本批 | 后果 |
|---|---|---|---|
| 分母 | 207 全量（`sample=207`） | 207 全量 | ✅ 可比 |
| 重复 | `repeat=1`、`require_stable=false` | `repeat=2`、`require_stable=true` | ❌ **pass^k 不可比**：该批只有单次通过率，没有稳定性结论 |
| 种子 | 每次尝试都用同一个 `seed=42` | 逐次派生（K08） | ❌ **jaccard 不可比**：该批的"高稳定"是同种子复现，不是模型稳 |

一句话：**本批的通过率只能与"同代＋同 207 全量＋同 repeat"的批次比；与 `20261106-night` 只能比"哪些用例失败了"，不能比任何比率。**

## 四、四种"不得引用"的情形

| 情形 | 判据 | 为什么不能引用 |
|---|---|---|
| 门禁 `invalid` 的场次 | Key 禁用／配额耗尽／网关内容审核拦截／`max_tokens` 截断 | 通过率反映的是网关，不是模型 |
| 存在 `precondition_failed` 的场次 | 沙箱 fixture 写不进 | C14′ 起已不计入分母；**复跑旧 run 时仍要看** |
| 稳定性数字 | 输出里 `cases_with_single_seed > 0` | 变序机制没生效，本轮稳定性是假的 |
| 单次通过率 | `require_stable=true` | 结论只认 pass^k；单次通过率只能当 `pass@k` 的上界线索 |

## 五、分数怎么读（三个不要）

1. **不要把 Strict 与 Standard 混着比**：Strict 要求全部断言通过，Standard 只判 Critical，两者分母不同。
2. **不要把 κ 判"仅报告"的 Critical 当成"已通过"**：κ 落在 0.60–0.80 时能力类判据只能报告不能拦。本批 κ=0.8412 在可阻断档，**这是本批能当基线的前提之一**；κ 一旦回落到 0.80 以下，本批的阻断结论要重算。
3. **不要把 Wilson 区间当准出线**：`wilson_interval` 只在 `report.py`（展示）与 `drift_check.py`（漂移比对）出现，`gate.py` 全文不引用——它是排序与抽检工具，不是门禁。
