# AQG 的自验收：为什么它位于 L5

> **本文只登记，不实现**（K03）。它回答一个问题：谁能给"门禁"本身定验收标准。
> 结论先行：AQG 判的是别人交付物，但它自己也是交付物，所以它必须有自己的验收标准，且这份标准位于规约体系的最外层（L5）。

## 一、定位

「规约」的对象是交付物。AQG 的存在是为了给**被测 agent 的交付物**立规约（做什么／背景／不能做什么／怎样算成功），而 AQG 自身产出的是"一份判定"——它同样要被规约，否则"这个门禁可信吗"就只能靠口头背书。

因此 AQG 位于最外层：**它对别人立规约，又必须接受针对"判定系统本身"的规约**。

> 五层的具体分层名称以讲者原始材料（快手技术沙龙第六期 · 朱少民《企业级智能体工程化落地》）为准；**本仓库未落档原始分层，故本文不转述层名，只登记结论与验收标准**。
> 与"云帆五层／星慧／四阶段模型"无关——那是平台架构叙事，本项目明确不复述（见 [`../kuaishou-tech-talk-06/00-待做清单.md`](../kuaishou-tech-talk-06/00-待做清单.md) §九.2）。

## 二、L5 自身的三条验收

| # | 验收项 | 判据 | 现状 | 缺口归属 |
|---|---|---|---|---|
| 1 | **回归全绿** | `python -m pytest -q` 636 条通过 ＋ `scripts/verify.py` 离线层 13 项全过（含数据集重建确定性、C01 判据自检、C04 可判率与重复率、C03 `spec_leak`、K13 case lint、C14′ fixture 预检、M1 台账入账、dry-run 采样） | ✅ 已达成，且是唯一**自动**的一条 | — |
| 2 | **性能恶化阈值** | 需要延迟分位（如 p95）与 token 经济性阈值，越线即判不合格 | ❌ **确实没有**：整条门禁链上只有三个数值阈值——`jcv_threshold=0.6`（判负，`judge.py:1453`）、`min_valid_rate=90`（有效率，`gate.py:172`）、`breaker_threshold=5`（熔断，`run_eval.py:100`），默认值均在 `config.py`。**没有任何延迟或成本红线** | **K19**（P2，随切代窗口一并落地） |
| 3 | **无新增高危** | 同一代际内，本次改动前后台账 `open` 的 critical／high 条目数不增加，且没有新增 `regressed` | ⚠️ **半缺口**：数据出得来（当前 547 条台账、`open_risks` 302 ＝ critical 102 ＋ high 200、`regressed` 5），但**没有判据**把它变成门槛；C10 供应链的 `pip-audit` 是**咨询级**、不阻断 | **K14／K17** 落地时一并消费 |

## 三、为什么第 2 条不能省，也不能现在补

- **不能省**：聚合墙钟（`case_time_budget`，默认 480s）触发后记 `Time_Budget_Exceeded` 并计入 Strict 失败。没有延迟阈值时，"慢"与"不稳"在稳定性指标里是**同一堆数字**——慢模型（如平均 155s 的 `diandian-dots3-note-pre`）会天然多得分失败，Report 里无法把这两件事分开。
- **不能现在补**：加阈值就是改判定。按纪律，凡改判定必须打包进切代窗口，**绝不为单项单独开窗**（见 `CONTRIBUTING.md`「评测用例与切代」与 [`../../AGENTS.md`](../../AGENTS.md) 纪律 2）。所以本条只登记为缺口，实施在 K19。

## 四、第 3 条的人工替代法（K19/K17 之前）

没有自动判据，不等于没有做法。同一代际内比两次台账即可：

```bash
# 改动前留底
cp reports/risk_ledger.json /tmp/ledger-before.json
# 跑改动后的批次 / 或只重算台账
python scripts/run_eval.py --suite smoke --limit 18
# 比对 open 的 critical/high 与 regressed 是否增加
python - <<'PY'
import json
a = json.load(open('/tmp/ledger-before.json'))['entries']
b = json.load(open('reports/risk_ledger.json'))['entries']
def count(E, level):
    return sum(1 for v in E.values() if v.get('risk_level') == level and v.get('status') in {'open', 'regressed'})
for lv in ('critical', 'high'):
    print(lv, count(a, lv), '->', count(b, lv))
PY
```

这条比对**只在同一代际内成立**；跨代数字不可直接相减（跨代重新基线为 `open`，见 README「数据集代际指纹」）。

## 五、明确不做

1. 不复述平台架构叙事（云帆五层／星慧／四阶段模型）——AQG 是门禁，不是评测平台。
2. 不把 L5 验收做成"自己给自己盖章"：三条里只有第 1 条是自动的；第 2、3 条在 K19／K17 落地前，结论只能以人工核数＋批次口径声明的方式给出，并在声明里写明"未自动化"。
3. 不在本文新增任何判据数值——阈值从哪来、定多少，属 K19 的设计，本文只认领"这里缺一条"。
